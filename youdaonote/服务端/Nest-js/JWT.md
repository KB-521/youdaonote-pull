JWT（Json Web Token）声明一般被用来在身份的提供者和服务提供者间传递被认证的用户身份信息。



流程：

1. 用户使用用户名密码来请求服务器

1. 服务器进行验证用户的信息

1. 服务器通过验证发送给用户token

1. 客户端存储token，并在每次请求附送上这个token

1. 服务端验证token值，并返回数据



构成：

1. Header(头部)：

```json
{
    "alg": 签名的算法,默认HS256
    "typ": JWT (固定)
}
```

1. Payload(负载)：

```typescript
// 用来放实际需要传递的数据。以下是官方字段，供选用。
{
    iss: 签发人
    exp: 过期时间
    sub: 主题
    aub: 受众
    nbf: 生效时间
    iat: 签发时间
    jti: 编号
    // 还可以定义私有字段
}
// payload部分是客户端可解密的, 不要放
```

1. Signature(签名)：

```typescript
// 对前两部分的签名，防止数据篡改。
// 签名产生公式：
HMACSHA256(base64UrlEncode(header) + "." + base64UrlEncode(payload),secret)
// secret: 密钥,这个密钥只有服务器知道, 不能泄露给用户; HMACSHA256: Header里知道的签名算法, 默认是HMAC SHA256;
// 算出签名后, 把三个部分拼接成字符串, 每个部分之间用“.”分隔。

```



特点：

1. JWT默认是不加密的，但可以加密处理。生成原始Token后可以使用密钥在加密一次。不加密的情况下不要把秘密数据放进Token。

1. JWT不仅可以用于认证，也可以用于交换信息。有效使用JWT，可以减少服务器查询数据库次数。

1. JWT最大缺点是：由于服务器不保存session状态，因此无法在使用过程中废止某个Token，或者更改token的权限。

1. JWT本身包含了认证信息，一旦泄露，任何人都可以获得该令牌的所有权限。为了减少盗用，JWT有效期不宜设置的太长，对于一些重要权限，因进行二次认证。

1. 为了减少盗用，JWT不应使用HTTP协议明码传输，要使用HTTPS协议。
