1. npm 模块安装机制

- 发出 npm install 命令；

- 查询node_modules目录之中是否已经存在指定模块

  若存在，不再重新安装；

  若不存在

npm向registry查询模块压缩包网址

下载压缩包，存放在根目录下的.npm目录里

解压压缩包到当前项目的node_modules目录



1. npm 实现原理

输入npm install后会经历如下几个阶段:

I. 执行工程自身的 preinstall

当前 npm 工程如果定义了preinstall钩子此时会被执行；



II. 确定首层依赖模块

首先要做的是确定工程中的首层依赖，也就是 dependencies 和 devDependencies 属性中指定的模块。

工程本身是整颗依赖树的根节点，每个首层依赖模块都是根节点下面的一颗子树，npm 会开启多进程从每个首层依赖模块开始逐步寻找更深层级的节点。



III. 获取模块

获取模块是一个递归的过程：

- 获取模块信息。在下载模块之前首先要确定其版本，这是因为package.json中往往是semantic version（语义化版本）。此时如果版本描述文件有该模块信息直接拿即可，如果没有则从仓库获取。

- 获取模块实体，上一步会获取到模块的压缩包地址，npm会用此地址检查本地缓存，缓存中如果有就有就直接拿，没有则从仓库下载。

- 查找该模块依赖，如果有依赖则返回第一步，如果没有则停止。



IV. 模块扁平化（dedupe）

上一步获取到的是一颗完整的依赖树，其中可能包含大量重复模块，在npm3以前会严格按照依赖树结构进行安装，因此可能会造出模块冗余。

从npm3开始默认加入dedupe过程，它会遍历所有节点，逐个将模块放在根节点的下面，也就是node_modules的第一层。当发现有重复模块时，则将其丢弃。

这里需要对重复模块进行一个定义，他指的是模块名相同且semver兼容。每个semver都对应一段版本允许范围，如果两个模块版本允许范围存在交集，那么就可以得到一个兼容版本，而不必版本号完全一致，这可以使更多冗余模块在dedupe过程中被去掉。



V. 安装模块

这一步会更新工程中的node_modules，并执行模块中的生命周期函数（按照preinstall、install、prepare的顺序）。



VI.  执行工程自身生命周期

当前npm工程如果定义了钩子此时会被执行（按照install、postinstall、prepublisth、prepare的顺序）。

最后一步是生成或更新版本描述文件，npm install 过程完成。
